<!-- AREA -->
**The CLI surface.** Arguments, flags, exit codes, `--json` envelopes (`{version, success, data}` or `{version, success:false, error, exitCode, suggestion}`), sessions (start, `status`, `stop`, `cleanup`, `sessions`, `--state`), and interrupts (Ctrl-C → exit 130, SIGTERM → 143). Make bdg exit 0 on a failure or non-zero on a success, print an envelope that doesn't match its exit code or isn't valid JSON, print a stack trace, leave processes or files behind, report a session as running when it's dead (or the reverse), or have two sessions/commands corrupt each other.
<!-- TARGETS -->
- **Arguments**: values with spaces, quotes, newlines, `=`, leading dashes, unicode, empty strings, very long strings, numbers out of range (`--last 0`, `-1`, `1e9`, `NaN`), flags repeated or given twice with different values, a flag that belongs to another command, `--` before arguments.
- **Envelopes**: every command with `--json` on success and on its main failure: is stdout exactly one JSON document, does `success` match the exit code, is `exitCode` in the body the real exit code, is there a `suggestion` on errors, does anything leak to stdout in human text.
- **Sessions**: two `bdg <url>` at the same time in one `BDG_SESSION_DIR`; a command while the session is starting or stopping; killing Chrome (`kill` of the PID in the session dir) or the daemon and then running `status`, a DOM command, `stop` and `cleanup`; a stale `daemon.sock` or `daemon.pid` file from a previous run; a read-only or full session directory; `BDG_SESSION_DIR` with spaces.
- **Interrupts**: Ctrl-C and SIGTERM during start, during a long `wait`, during `console --follow` or `network list --follow`, during a screenshot of a huge page, during `cdp` with a slow method; then check exit code, message, and whether the session still works and nothing is left over (`ps`, files).
- **Output to pipes**: `bdg … | head -1` (EPIPE), stdout closed, very large outputs, `NO_COLOR`, a non-TTY stdin.
<!-- COVERED -->
generated invocations from `--help --json` checked for: one JSON document on stdout with `--json`, `success` matching the exit code, no stack traces, exit codes in the documented ranges, suggestions on errors (a 6000-run fuzzer; missing suggestions on attach failures and on `dom screenshot` option checks are known); Ctrl-C during start, screenshot and `page switch`.
